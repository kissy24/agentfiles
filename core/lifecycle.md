# AWF Lifecycle

AWF-SPEC-001 / 0.1.0-draft。[5契約](contract.md)を、次の4機能で実践する。固定的な工程順や、毎回の定型報告を強制しない。

| 機能 | 確認すること |
| --- | --- |
| Understand | 目的、成果、制約、権限、情報源、完了条件。不確実性と許容できる仮定 |
| Act | 許可範囲内で手段を選び実行。必要なPracticeだけ使用 |
| Verify | 成果と影響を適切な根拠で確認。失敗、未実施、適用範囲を区別 |
| Adapt | 根拠に応じて続行・修正・完了・相談・中断を判断 |

## 反復と停止

- MUST：検証に失敗したら成功を宣言しない。原因調査・修正・別の検証・中断のいずれかを選ぶ。
- MUST：同じ失敗を無制限に繰り返さない。新しい根拠・成果が得られない場合は、方針変更・相談・中断へ移る。
- MUST：権限外の操作は実行前に承認を得る。許可待ちの操作と、継続できる作業を区別する。
- MUST：終了時に結果・検証状況・残課題を示す。
- SHOULD：複雑さ・費用・リスクに応じ、反復上限・時間・リソース予算を設定する。数値はタスクで選び、全用途共通の回数は設けない。

待機は実際に進行中の処理と確認方法を把握して行う。再開時は状態記録だけを信じず、成果物・権限・実行結果を再確認する。

## 状態

作業中は `working`、検証中は `verifying` を使用できる。これは本実装の表示上の慣例であり、Coreが全環境に強制する値ではない。終了・人間への引き渡しでは次を区別する。

| 状態 | 判定 | 報告内容 |
| --- | --- | --- |
| `completed` | 合意した完了条件をすべて満たした | 成果物と検証根拠。別途必要な人間の受容を代行しない |
| `partial` | 成果はあるが条件が未達 | 完了範囲と不足事項 |
| `blocked` | 情報・権限・環境不足で進行不能 | 障害と解除に必要な対応 |
| `approval_required` | 人間の判断・許可待ち | 判断事項、対象操作、リスク、選択肢、承認者 |
| `stopped` | 予算、反復上限、リスク等で中断 | 中断理由と再開条件 |

完了条件に必要な検証が未実施・失敗・根拠不十分なら `completed` にしない。対象外の検証も、その範囲が分かるよう報告する。人間の受容が完了条件に含まれる場合は、その判断まで完了にしない。複数の事情がある場合は主な状態を1つ選び、残課題に他の事情を示す。

## 引き継ぎと再開

承認待ち・中断・引き継ぎ・完了の時点で、目的、状態、現在の焦点、重要判断と理由、根拠、残課題を整合させる。必要に応じて次の行動・更新日時も残す。

再開する人・エージェントが、成果物の場所、最後の検証結果、未確認事項、必要な承認と許可範囲を特定できるようにする。次に検証することを具体的に示す。全文ログの貼付や内部推論の保存は不要。

再開時は現状と記録の差を確認し、目的・権限・完了条件を再評価して適切な機能へ戻る。新しい範囲への許可は過去の承認から推定しない。
