## MVP受入基準（仕様§11.2）

| 基準 | 評価と直接の根拠 |
| --- | --- |
| 汎用性 | 開発の境界条件修正と導入方式調査が同一Coreを参照。両方で目的・許可・検証・状態を表現 |
| 軽量性 | 最小導入は3ファイル、必須実行ツールなし。会話による状態可、全欄転記不要。導入スモークテストで配置を確認 |
| 自律性 | Coreと入口が許可範囲内の手段選択を委ねる。Practice選択なしで始められ、一律の工程・報告頻度・反復上限なし |
| 透明性 | S4で状態だけから目的・焦点・判断・根拠・残課題・次の行動を読み取れることをレビュー |
| 根拠 | RED/GREENの実行記録と、出典照合レポート。統合・本番・費用測定の未実施を明記 |
| 境界 | S3が本番操作を保留し、許可・制御・承認者・リスク・選択肢を表示。技術的強制は環境に委ねる |
| 再利用性 | S5でtdd/securityからevidence/context-managementへ変更し、Coreを再定義せず調査を完了 |
| 移植性 | Codex入口・配置・公式資料に基づく接続手順を提供し、配置後の参照を実検査。Coreに製品依存なし |

## 検証範囲と再現

実行したコマンドと出力は[verification.txt](verification.txt)。`python3 scripts/verify.py` は配布物・ローカルMarkdownリンク、Practiceの項目、両例のCore参照、状態の項目、実際の導入コマンド、既存入口を壊さないこと、修正前後の同じ3テストを検証する。一般のAWF適合判定器ではない。

[6シナリオ](scenarios.md)は文書と判断・状態表示の定性的な適合をレビューした。調査レポートはSPEC§2.1、§4、§6、§7、§9.1と照合し、比較表は推論、費用・理解速度は未測定として分離されていることを確認した。

Codexの入口方式は[公式資料](https://learn.chatgpt.com/docs/agent-configuration/agents-md)を確認し、ローカルCLIは `codex-cli 0.167.0` と確認した。独立した新規Codexセッションでの読込・自律運用試験は未実施。Adapterは手動の指示接続までを提供し、状態自動同期、ランタイム強制、他製品Adapterは提供しない。これらを参照実装の完成根拠へ含めていない。

未測定の運用品質や安全性を含む包括的な「AWFが常に遵守される」という宣言は行わない。対象環境へ導入したらAdapter記載の接続確認を行い、その環境の権限・承認制御も確認する。

PR提出前に[セキュリティレビュー](security-review.md)を追加実施。導入手順の許可リスト、最小の子プロセス環境、パス境界、上書き・symlink拒否、秘密情報検査の検証範囲と制約を記録した。
