# 運用と実装判断

AWF 0.1.0-draft。原仕様の第13節に対し、参照実装では次を選びました。全用途へ固定する追加要件ではありません。

| 未決事項 | 本実装の判断 | 理由・変更時の扱い |
| --- | --- | --- |
| Coreのコピー／外部参照 | 初期導入はコピー | オフラインで参照可能。外部参照も可だが版とアクセス性を確認 |
| Codexの配置 | ルートAGENTS.md → .awf/core | 製品依存をAdapter内に閉じる。既存入口は統合 |
| 状態表示 | 小規模は会話・Issue、長時間は任意ファイル | 必須ファイルを増やさない。正本を決め、節目で更新 |
| ルール競合 | 実際の命令階層・実行制約を尊重し、抵触操作を停止・相談 | Coreを弱める例外を黙認しない。影響しない作業は継続 |
| Practicesの互換性 | ID、独立した版、対応Coreを各文書に表示 | パーサー・依存解決器は導入しない。条件を読んで選択 |
| 反復・費用 | タスクごとに上限を選ぶ | 回数一律化を避ける。進展のない反復は方針変更・相談・中断 |

## 更新する場合

Core変更は、防ぐ失敗・変更理由・互換性への影響・既存導入の移行方法を説明します。仕様の正本は [SPEC.md](../SPEC.md)、入力資料は原文保存とします。仕様と実装が異なる場合は差分を明示して是正します。

Practicesは独立に改訂できます。必要なものを選び直し、不要なら入口から参照を外します。Coreはそのまま維持します。既存の参照先を消す前に利用箇所を確認します。

Adapterは公式の接続方法が変わった際に確認日・手順・対応表を更新します。未検証や未対応を対応済みにしません。別製品への追加時もCoreの意味を再定義しません。

ルール追加には、防ぐ失敗・測定する効果・追加負担の説明を添えます。使われない、または効果が確認できないルールは削除・簡素化します。

## 初版の評価

定性的な6シナリオと8受入基準を[適合性記録](conformance.md)で評価します。容易に確認できる指標は、最小導入の追加ファイル数（3）、Coreを変更しない適用例の数（2）です。状態ファイルとPracticesは任意なのでこの3には含めません。

理解までの時間、不要な確認回数、実利用での境界超過阻止率、トークンや費用の改善は未測定です。実運用では必要な少数の指標から収集し、導入前後を比べます。初版の文書レビューから改善率を推測しません。
