# 技術調査への適用

題材：オフラインでも参照できる、小規模チーム向けAWF導入方式の調査。成果は[調査レポート](report.md)。Coreとテンプレートの設計資料を一次情報として照合します。

- 目的：コピー／外部参照、会話／ファイルの選択肢を比較し、導入案と制約を提示する。
- 完了条件：仕様が必須とする性質と任意手段を区別し、比較・提案・未検証点に根拠を付ける。実運用の費用削減の証明は依頼の範囲外。
- 許可：本リポジトリの資料閲覧と調査文書の編集。外部環境の変更、秘密情報送信、実運用への採用決定は含まない。
- 役割：AIが調査・照合・報告。依頼者が範囲・採用・受容を判断する。
- Core：[共通契約](../../core/contract.md)、[共通ライフサイクル](../../core/lifecycle.md)。開発例と同じ文書。
- Practices：[evidence](../../practices/evidence.md)、[context-management](../../practices/context-management.md)。TDDとpre-commitは不要なので選択しない。
- 手順：仕様の該当節を理解 → 比較表を作成 → 主張と原文を照合 → 根拠のある提案と未検証点を分けて報告。

成果と出典のレビュー結果は[検証記録](../../docs/conformance.md)にあります。[途中から参加する人向けの状態](task-status.md)、[根拠不足時の例](status-partial.md)、[中断・再開の例](handoff.md)も参照できます。

調査範囲が費用削減の実測や実環境への導入へ広がる場合は、元の範囲内かを確認し、範囲外なら依頼者と完了条件・権限を合意します。開発例のテストを調査の完了判定へ流用しません。
