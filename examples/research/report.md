# オフライン参照を重視したAWF導入方式の調査

調査日：2026-11-10。対象版：AWF-SPEC-001 / 0.1.0-draft。

## 確認した事実

| 主張 | 根拠と確認箇所 | 照合結果 |
| --- | --- | --- |
| 必須なのは5契約の性質であり、特定のファイルやツールではない | [SPEC](../../SPEC.md) §2.1、§4 | 原文で確認 |
| 状態表示はMarkdown、Issue/PR、ダッシュボード等から選べる | [SPEC](../../SPEC.md) §4.4、§6 | 原文で確認。常時自動更新は必須でない |
| 初版はコピー・参照リンク・テンプレート適用でよく、専用CLIは必須でない | [SPEC](../../SPEC.md) §9.1 | 原文で確認 |
| TDD等は任意Practiceで、調査に一律適用しない | [SPEC](../../SPEC.md) §7、§10.2 | 原文で確認 |
| 本実装はコピー配置後にCore同士を相対参照できる | [契約](../../core/contract.md)、[ライフサイクル](../../core/lifecycle.md)、[Adapter](../../adapters/codex/README.md) | 文書のリンクを確認。配置検証の結果は[検証ログ](../../docs/verification.txt) |

これらは同じ仕様とその実装の照合であり、独立した複数の実運用調査ではありません。

## 比較と提案

| 選択肢 | この用途での利点 | 制約 |
| --- | --- | --- |
| Coreをコピー | 配布済みファイルをオフラインで読める。適用版が固定される | 新版への更新と差分確認が必要 |
| Coreを外部参照 | 中央の文書を参照でき、重複コピーを減らせる | 参照先へのアクセスと版固定の方法が必要 |
| 状態を会話・Issueに表示 | 既存の作業場所で目的や進捗を確認できる | 次の担当者が履歴へアクセスできる必要がある |
| 状態をファイルに表示 | 成果物と一緒に引き継げる | 更新が必要で、未更新なら現状とのずれが生じる |

上表の利点・制約は文書構成と運用方式からの推論です。測定結果ではありません。

提案：この依頼の「オフライン参照」を満たすためCoreをコピーし、小さな作業は会話、長時間・引き継ぎ作業は任意の状態ファイルを使います。最小導入は入口1つとCore2つの計3ファイルで、Practiceや状態ファイルは追加しなくても開始できます。これは[導入配置](../../adapters/codex/README.md)から数えた値で、全方式共通の要件ではありません。

## 未検証と受容

トークン削減率、費用削減率、理解までの時間、他チームでの効果は未測定です。「導入すれば費用が半減する」とは結論しません。状態ファイルの自動同期も未提供です。

完了条件である選択肢比較と出典照合は実施しました。実運用の採用・外部環境への反映は依頼者の判断です。効果測定が必要なら、対象タスクと比較条件を決めた追加調査として扱います。
